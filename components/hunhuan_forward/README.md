# HunHuan 群转发 · AstrBot 插件

按 HunHuanBot 当前版本的可观察行为独立实现的 AstrBot 兼容插件。
功能是按规则跨群发送原消息段，并在源群提供两分钟内可用的批量撤回码。

## 1.1.0 可视化控制台

在 AstrBot 插件列表找到“HunHuan 群转发”，打开插件页面“群转发控制台”。当前本机也可使用 [控制台入口](http://127.0.0.1:6185/plugin-view/astrbot_plugin_hunhuan_forward/console)，浏览器访问需要登录 AstrBot。

- **手动发送**：从机器人已加入的群列表中搜索群名/群号，多选接收群；输入文字、选择/拖入/粘贴图片，预览后发送。支持纯文字、纯图片、图文组合。最多 5000 字、6 张图片；每张最多 5 MB、合计最多 12 MB，支持 PNG/JPEG/GIF/WebP。
- **发送记录**：显示逐群回执，成功消息可在两分钟内撤回；失败的撤回可在原有效期内重试。记录与撤回映射仅保存于内存，最多 50 批；重载或重启后清空。
- **关键词规则**：新增、编辑、删除规则，选择监听源群和转发目标群，选择前缀或包含匹配；关键词可逐个添加和删除，可启用/暂停规则并限定机器人。
- **检测测试**：输入测试文字和源群，查看规则是否命中、会发往多少个目标群；测试不会发送消息。
- **立即生效**：从控制台保存规则或间隔后立即生效，不需要重载，也不清空原有自动转发撤回码。

页面通过 AstrBot 现有鉴权和插件页面桥接访问接口，不另开公开端口。手动发送不自动重试；重复提交同一批请求会返回已有结果，避免重复发送。没有成功回执的群标记为“结果待核对”，请到群内核对。自动转发仍保留原库的异常重试行为。

`rules[].platform_id` 为空时适用于全部 OneBot 平台实例；非空时仅作用于选定机器人。`rules[].enabled` 默认 `true`。原版配置不含这两个字段时仍可使用。新增 UI 规则会拒绝空关键词，避免误设为匹配所有消息。

## 安装和使用

1. 使用 AstrBot 4.10.4 或更新版本，接入 aiocqhttp（OneBot v11）及 NapCat。此版本下限来自配置模板 API，尚未进行该版本的真实启动验证。
2. 在 AstrBot 插件管理中上传本插件 ZIP；也可以解压插件目录到 `data/plugins/astrbot_plugin_hunhuan_forward/` 后重载。
3. 在插件配置的“转发规则”中添加规则，填写源群、目标群、匹配方式和关键词，保存并重载插件。默认规则为空，不会向任何群发消息。
4. 确保机器人已加入源群和目标群，且有发送权限。源群消息必须能进入 AstrBot 事件处理流程；群白名单、平台连接及其他插件拦截可能影响接收。普通消息匹配无需 @ 机器人或调用模型。
5. 在源群发送如“重要：今晚活动”。转发结束后，机器人引用原消息回复撤回码。在同一个源群发送 `撤回a1b2c3d4` 即可撤回对应目标消息。

没有额外 pip 运行依赖，不需要部署 NcatBot，也不需要在本插件中重复填写 NapCat 地址和 Token。

## 配置示例

参见 [config.example.json](config.example.json)。源群和目标群支持整数群号，也支持字符串形式的群号。

从原库迁移时，将原 `plugin.plugin_configs.ForwardBotPlugin` 下的 `send_interval_ms`、`rules` 放入本插件配置。使用 WebUI 模板时每条规则还会包含 `__template_key: "forward"`；该字段不参与匹配。群号列表和关键词列表的内容均可照搬。不要复制整个 NcatBot 的 `config.yaml`。

| 配置 | 行为 |
| --- | --- |
| `send_interval_ms` | 默认 500 毫秒，转发、源群回执、撤回共用一个间隔 |
| `rules[].name` | 非空规则名 |
| `rules[].type` | `prefix`：任一关键词作为前缀；`keyword`：包含任一关键词 |
| `rules[].source_groups` | 非空源群列表 |
| `rules[].target_groups` | 非空目标群列表，自动排除来源群本身 |
| `rules[].keywords` | 非空关键词列表，区分大小写；文本两端空白不参与匹配 |
| `rules[].forward_prefix` | 保留兼容，和原库当前实现一样，不添加到消息中 |

## 保持的行为

- 按原始消息中的文字段匹配；命中后读取原消息并原样提交消息段到目标群，以机器人身份发送。不是合并转发卡片，也不伪装成原作者。
- 图片、语音、视频、@、引用等消息段不经过 AstrBot 的二次转换。纯图片等没有文字的消息不会命中关键词规则，与原库一致。实际发送能力和显示由 QQ/NapCat 决定。
- 忽略机器人自己的消息、私聊、以 `/` 开头的消息；撤回指令优先处理，不参与转发。
- 一条消息可命中多条规则。同一目标在多个命中规则中出现时会发送多次，与原库一致。
- 转发接口异常时最多重试两次，总计三次尝试；两次尝试间等待 0.5 秒。网络超时可能发生“服务端已发送但客户端未收到结果”，原库的这一重试语义也可能带来重复消息。
- 已返回结果但缺少目标消息 ID 时不重发，回执会说明无法用撤回码撤回。源群回执失败也不触发重发。
- 转发完成后生成随机 8 位十六进制撤回码，有效期 120 秒。源群任何成员均可使用，其他群不能使用。
- 部分撤回失败时，仅保留失败的 ID，可在原有效期内用同一码重试；不延长有效期。已受理的撤回即使中途过期，也继续执行全部目标。
- 并发使用同一个码只执行一批撤回；到期自动清理；重启、卸载、重载插件后缓存失效。

## 适配边界

本插件只支持 aiocqhttp + NapCat 的 QQ 群消息。QQ 官方机器人及其他平台不能保证同等跨群发送和撤回能力，此版本直接忽略这些平台的事件。多机器人环境还会按平台实例、机器人账号、源群隔离撤回码，比原来单机器人应用的隔离范围更细。

AstrBot 的白名单、事件过滤、其他插件的拦截和大模型回复流程属于宿主行为；原应用是独立机器人，无法只靠本插件消除全部宿主差异。成功转发不阻断其他 AstrBot 插件；撤回指令处理后停止事件传播，避免额外模型回复。

**当前状态：已在本机 AstrBot 真实安装并加载，能读取 NapCat 的实际群列表；浏览器验证了群选择、图片预览、关键词编辑及命中检测。发送/撤回逻辑通过模拟测试，尚未进行真实群消息发送验收。**

首次上线可使用两个测试群验收：文字、带关键词图片、引用、@、语音/视频混合消息的显示；源群其他成员使用撤回码；跨群使用码被拒绝；超过两分钟后失效；插件重载后旧码失效。机器人须已在测试群内。
