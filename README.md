# 莫古环的魔法水桶

FF14 狩猎播报与群消息工具，适用于 AstrBot 4.29.1+。S怪地图标点、可触发提醒、狩猎车提醒和图片指令、群转发、查漏采集、芒果广播与手动群发共用 WebUI。

公开发行版所有自动转发规则、来源群和目标群默认留空；请先接入机器人并按需设置。旧版用户的配置保存在 AstrBot 数据目录，升级沿用，不会被默认配置替换。自动狩猎车提醒默认仅发文字，接收群留空时不发送。图片由 `/车图 大区`、`/车线 编号` 等指令单独获取。

地图在发行 ZIP 内使用无损 WebP 保存，首次使用恢复到插件数据缓存；图像像素不变。完整 Git 源码保留原 PNG，发行 ZIP 通过 `.gitattributes` 排除重复 PNG 与测试资料，控制在市场 16MB 限额以内。首次恢复地图需要 Pillow 的 WebP 支持。Linux 图片生成需要安装中文字体（如 Noto Sans CJK）。

## 控制台

新增“车表与指令”标签，读取 [FFXIV 狩猎车时间顺序表](https://ffxivhuntcn.com/ShiJianShunXu) 的公开排班接口。默认 `/发车`、`/车表` 查询豆豆柴未来24小时；`/车表 鸟`、`/车表（莫古力）`、`/车表 全部` 可指定大区。单个大区按下一次发车时间排序；选择“全部大区”时跨区按时间混排，不再分组；暂停班次跳过，已过时刻计为明天，班次限定说明保留为文字备注。

在新标签内可新增、删除和停用规则，修改指令别名、默认大区、查询时长、显示数量、整段回复与单班模板，也可选择固定文字回复。`{车表}` 插入动态列表，单班模板支持时间、服务器、版本、始发站、水晶及班次备注等变量。保存后立即生效；页面预览不会向群发送消息。查询数据缓存60秒；读取失败会说明失败，不编造排班。较长文字分段回复。

在 AstrBot 插件管理中打开本插件的 `console`（S怪控制台）。控制台使用 AstrBot 登录权限，不额外开放公网端口。

1. 选择发送机器人。
2. 在「接收群号」中每行填写一个群号，不需要机器人名或其他前缀。
3. 在「监听范围」选择大区与服务器，点击「添加监听」。选择「全部服务器」可监听整个大区；指定服务器可逐个添加。
4. 在「播报模板」分别编辑「实际出现播报」和「可触发提醒」，可点击变量插入、查看示例预览；各有独立的保存、恢复按钮。
5. 点击「保存配置」生效。

可删除整个大区，也可移除单个服务器。删除最后一个服务器会移除该大区项，不会自动改成监听全部。监听范围清空后停止连接，接收群清空后停止该机器人的播报。修改接收群时保留其他机器人的设置。

可选大区为豆豆柴、陆行鸟、猫小胖、莫古力，服务器列表从网站资源读取。默认仍为豆豆柴全服；更新不会自行扩大范围。四大区简称依次为「狗、鸟、猫、猪」。

控制台包含接收设置、监听范围、播报模板和最近发现记录。样式参考[狩猎点位图](https://119.29.119.179/Arank/)，采用蓝色按钮、卡片和侧边导航；左下角可切换明暗主题。首次跟随系统，手动选择后保存在当前浏览器，刷新后保留。

## 播报与地图

动态格式：

`库啵，发现一只{等级}S: {怪名}出现在[{大区简称}-{服务器}] {地图} ({坐标})`

可用变量：`{等级}`、`{怪名}`、`{大区}`、`{大区简称}`、`{服务器}`、`{地图}`、`{坐标}`、`{X}`、`{Y}`、`{分线}`。`{坐标}` 只含 `18.4, 15.1`，括号由模板自行添加；坐标缺失时显示待更新。`{地图}` 保留分线后缀，`{分线}` 为分线编号，无分线时为空。支持换行，最多2000字符；原样显示花括号使用 `{{` 和 `}}`。错误变量或格式表达式不能保存。预览只使用示例数据，不发送群消息。

模板保存后用于后续群播报和坐标补充；地图缺失、坐标缺失或坐标补充仍附必要状态提示。手工修改配置文件产生无效模板时，播报回退默认模板。

## S怪可触发提醒

默认启用全部13种，可在「可提醒的 S 怪」列表逐只勾选，也可全选或全不选；点击「保存勾选」「保存提醒设置」或「保存配置」生效。全不选表示停止可触发提醒，不影响实际出现播报。取消勾选会取消该怪的待发提醒，重新勾选不补发旧窗口。

沿用接收群和监听范围，读取[参考站悬浮窗](https://119.29.119.179/Srank/)使用的实时计时、共享击杀与维护记录。参考站目前提供豆豆柴、莫古力大区；其他大区的实际出现播报继续正常工作，可触发提醒会明确显示参考数据尚不支持。

只覆盖悬浮窗的13种S：护土精灵、火愤牛、千竿口花希达、虚无探索者、刚德瑞瓦、夺心魔、伽洛克、雷德罗巨蛇、咕尔呱洛斯、伽马、巨大鳐、布弗鲁、厌忌之人奇里格。按参考站的天气、ET时段、月相及正常/维护CD，判断具体服务器是否进入绿色「可触发服」阶段；灰色「已强制」阶段按原站规则不触发这类提醒。

默认文字：

`库啵，{等级}S: {怪名}可以触发啦，目前有概率出现在{服务器列表}等，冒险者大人们快去尝试呀！`

支持独立变量 `{等级}`、`{怪名}`、`{服务器列表}`、`{大区}`、`{大区简称}`、`{服务器}`、`{地图}`、`{分线}`。`{服务器列表}` 例如 `[狗-伊修加德]、[狗-水晶塔]`，仅列出当前有效且在监听范围内的服务器；旧单项变量在多服时用顿号连接。提醒为文字，不附虚构坐标或地图。`trigger_message_template` 与实际出现的 `message_template` 分别保存。

按自定义间隔检查（默认60秒），首次启动、新增监听或数据恢复仅建立基线，不补发旧窗口。同一只怪的同一条件窗口，每群合并提醒一次；同时符合条件的服务器列在同一条消息中，随后加入该窗口的服务器不再单独补发。失败重试时重新筛选仍有效的服务器。状态持久化到 `s_trigger_state.json`，重载及从旧版升级不会重复发送已成功的窗口。

参考站的全量击杀快照约缓存15分钟；天气和游戏时间按当前时钟计算。快照超过20分钟、来源异常或计算规则未经重新校验时暂停提醒，并在控制台显示原因。可触发仅表示符合原站显示条件，不代表怪物已经出现或必定触发。未知网页脚本不会在插件内执行。

怪名、服务器和坐标来自发现报告，地图按怪物标识关联网站资料，等级按该怪物等级或所属版本确定。分线保留。图片默认512×512，只含完整地图和蓝点；不显示标题、页脚和坐标文字框。位置计算保留上报精度，消息显示一位小数。

只处理真正的 `FoundReport`，不把刷新窗口和死亡记录当成出现。进入监听前已有报告不补发；同服、同怪、同线、同次出现按群去重，发送失败重试，死亡/撤销/过期及移出监听范围会取消待发送。

## 数据与默认配置

- 断线补查间隔30秒，可设置10～120秒。
- 报告有效期300秒，可设置30～600秒。
- `listen_scopes` 以大区和服务器列表保存；单项 `servers: []` 表示该大区全服，整个列表 `[]` 表示不监听。
- `target_sessions` 是自动生成的内部群路由，控制台无需手工填写。
- 订阅、去重和地图缓存保存在 AstrBot 的 `plugin_data/astrbot_plugin_bear_tracker/`。

已校准的47张地图、938个候选点位与触发条件继续供后台及 `/熊资料` 查询使用，来源为[参考网站](https://119.29.119.179/Srank/)。实时蓝点始终使用实际发现坐标，不用候选点替代。坐标缺失或地图未知时不会猜测标点。

保留 `/熊计时`、`/熊资料`、`/S播报 开启`、`/S播报 关闭`、`/S播报 状态`。群命令启停需 AstrBot 管理员权限；控制台可管理配置指定的群。

- 记录和历史仅保存在 AstrBot 插件数据目录，不包含在发行包。配置回滚是完整配置回滚，请先查看差异；当前正在处理的消息会停止，旧触发窗口不会补发。


## 2.11.0 可触发提醒时间设置

在「接收与监听 → 播报模板 → 可触发提醒」设置检查间隔，默认60秒，允许20～3600秒。保存即唤醒检查任务；只改变可触发提醒的轮询，不改变实际出现的实时推送。间隔过长可能错过短暂的天气/ET窗口。

13只受支持的S怪各自有「进闸后等待」小时数，默认0，支持0～168个现实小时与小数（如0.5）。进闸起点为该服务器/分线的击杀或维护基准时间，加参考站对应最短CD；不从插件启动或天气窗口开始计时。等候后仍需满足当前天气/ET/月相及参考站的非强制可触发阶段，超过可触发期不发送。各服务器分别计算，再按原规则合并同怪同条件窗口，每群一次，后续服务器不分次补发。

改变某只怪的等待时间后会取消该怪旧待发记录，并将下一次有效快照作为基线；不补发当时已开放的旧窗口。之后新达到等待门槛的有效窗口正常提醒。重启不清空已发送回执，旧事件缺少进闸时间时不能绕过新门槛。间隔、怪物与等待时间、提醒模板分别可保存；原群、开关、静默时间与其他板块配置保持。


2.11.1 在每只可提醒 S 的名称下显示其常规与维护 CD（现实小时），使用参考站相同的最短 CD 加可触发期长度计算上下限。优先显示已校验的运行资料；尚未同步时使用随包校验资料。大区数据不同时分区展示，未知值不推测；等待时间、勾选、监听范围与所有已有配置不变。
